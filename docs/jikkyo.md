# 実況のコメントの中継

各家庭の denpa に、実況のコメントを配る機能です。NX-Jikkyo (tsukumijima さんが運営する非公式の実況サービス) のコメントを局ごとに 1 本の接続で受け、
ニコニコ実況 過去ログ API (同じく tsukumijima さん) の過去ログを取得してまとめて持ち、hub の独自コメントを受けて保存し、配ります。
独自コメントは、NX-Jikkyo が動いていれば NX-Jikkyo にも書きます。

コードは `src/DenpaHub/Features/Jikkyo/`、denpa の側は `src/lib/server/jikkyo-hub.ts` と `src/lib/jikkyo/` にあります。

この文書では、確かめたことには「確かめた」、推定には「推定」と書きます。

## なぜ hub を通すか

- **端末が外へ繋がない。** 端末は denpa のサーバにだけ繋ぎ、NX-Jikkyo と過去ログ API には hub が繋ぎます。端末の IP・ブラウザの User-Agent・denpa のアドレスは渡りません
- **NX-Jikkyo と過去ログ API への接続が減る。** 局ごとに 1 本で受け、過去ログは 1 時間ごとの塊で持つので、観ている端末の数だけ繋がずに済みます
- **NX-Jikkyo が落ちていても流れる。** hub の独自コメントは hub だけで受けて配ります

## やらないこと

- 公式のニコニコ実況のコメントを hub で受けて配ることはしません (ドワンゴの許諾を待っています)。足すときの形は [公式の入口](#公式の入口)
- 局の勢い (denpa のライブの「実況」タブ) は扱いません。denpa のサーバが NX-Jikkyo から読みます
- 書いた人が自分の書き込みを消す仕組みはありません (NX-Jikkyo でも消せません)

## 全体

```
denpa の端末 ─ POST /api/jikkyo/feed (ロングポーリング) ─▶ denpa のサーバ ─(局ごとに 1 本の SSE)─▶ GET /jikkyo/channels/{ch}/live ─(局ごとに 1 本)─▶ NX-Jikkyo
             ─ GET  /api/jikkyo/kakolog ─────────────────▶              ──────────────────────▶ GET /jikkyo/channels/{ch}/kakolog ─(1 時間の塊)─▶ 過去ログ API
             ─ POST /api/jikkyo/comments ────────────────▶              ──────────────────────▶ POST /jikkyo/channels/{ch}/comments ─▶ 保存・全部の家に配る
                                                                                                                  └─(利用者ごとの WS)─▶ NX-Jikkyo に書く
```

## エンドポイント

`JIKKYO_DATA` が無ければ、この機能は入りません (`/jikkyo/*` は 404)。どの応答にも [README](../README.md) の共通のヘッダが付きます。エラーは `{"error":"<名前>"}` です。

### 認証

**denpa のサーバは、hub が発行したトークンで名乗ります。** 番組ランキングと同じ形で、トークンは別に持ちます (ランキングに参加していない家も実況は使うため)。

- `POST /jikkyo/tokens` → `201 {"token":"<43 文字>"}`。32 バイトの乱数を base64url にしたもの。hub は SHA-256 だけを持ちます
- ほかのエンドポイントは `Authorization: Bearer <トークン>`。無い・知らないものは `401 {"error":"invalid_token"}`。denpa はトークンを取り直して 1 回だけやり直します
- 30 日使われなかったトークンは消します (使った時刻は 1 時間に 1 回だけ書き直します)
- **家の denpa であることは確かめられません** (ランキングと同じ限界)。発行に接続元のアドレスごとのレート制限を掛け、困ったときは[運営の方針](#運営の方針)で家や利用者を止めます

**家の ID** は `SHA-256(トークン)` の先頭 8 バイトの 16 進 (16 文字) です。独自コメントの持ち主として保存し、止めるときに使います。

### 局

局は `jk` と 1〜4 桁の数字です。形が違えば `400 {"error":"invalid_request"}`。
購読と書き込みは、方針の `channels` にある局だけを受けます。無い局は `400 {"error":"unknown_channel"}`
(NX-Jikkyo は知らない局を閉じるので、架空の局で繋ぎ直しを続けさせないため)。過去ログは古い局の録画のために形だけを見ます (NX-Jikkyo がもう持たない局の過去ログもあるため)。架空の局を訊かれても、取得できなかった塊は 60 秒失敗として持ち、その間は過去ログ API に訊き直しません。

### コメントの形

hub から denpa、denpa から端末まで同じ形です。

```json
{ "at": 1795000000123, "text": "本文", "mail": "184 red ue", "src": "nx", "id": "…" }
```

| 欄     | 説明                                                                                                                                     |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `at`   | 投稿時刻 (unix ms)。`nx` と `nicolive` は NX-Jikkyo の時計、`hub` は hub の時計                                                          |
| `text` | 本文 (前後の空白を落としたもの)。空のものと、`/` と英小文字で始まるもの (運営のコメントの形) は配りません                               |
| `mail` | コマンド。空なら欄ごと無い                                                                                                               |
| `src`  | `hub` (独自コメント)・`nx` (NX-Jikkyo に書かれたもの)・`nicolive` (NX-Jikkyo が公式のニコニコ実況から取り込んだもの。`user_id` が `nicolive:` で始まる) |
| `id`   | `hub` のものだけ。16 文字。denpa が自分の書き込みが戻ってきたのを見分けるのに使う                                                        |

NX-Jikkyo と過去ログ API の `user_id`・コメントの番号・プレミアムは、読んだその場で捨てます。

### `GET /jikkyo/channels/{channel}/live?after=<番号>&epoch=<印>`

その局のコメントを Server-Sent Events で流し続けます。

- 最初に `state`、続けて控え (直近 15 分・3000 件まで) のうち `after` より後の通し番号のもの (1000 件まで) を、あとは届くたびに送ります
- `epoch` が今のものと違う・`after` が無い・`after` が控えより古いときは、控えの全部 (1000 件まで) を送ります
- 送るもの
  - `event: state` / `data: {"nx":"up"|"down","epoch":"…"}`。NX-Jikkyo に繋がっているか。替わったときにも送ります。`epoch` は hub の起動ごとに替わります
  - `id: <通し番号>` / `event: comments` / `data: [<コメント>, …]`。通し番号は hub の中で 1 つで、増えるだけです
  - `event: ping` / `data: 1` を 15 秒ごと (Cloudflare の 100 秒の無通信の切断と、黙って切れた接続を見分けるため)
- 1 つのトークンで同時に開けるのは 8 本までです。超えたら `429 {"error":"too_many_streams"}`
- 方針の `channels` から外した局は、読み直したときに閉じます (denpa が繋ぎ直すと `unknown_channel`)

### `GET /jikkyo/channels/{channel}/kakolog?from=<unix ms>&to=<unix ms>`

- `0 ≤ from < to`、`to - from` は 3 日まで、`from` は今より前。違えば `400 invalid_request`
- `200 {"comments":[<コメント>, …],"complete":true|false}`。`[from, to)` のものを時刻の順に返します
- 中身は過去ログ API のもの (`nx`・`nicolive`) と独自コメント (`hub`) を合わせたものです
- **過去ログ API に届かなかった・20 秒で間に合わなかった塊があれば `complete: false`** (独自コメントと、間に合った塊は返します)。denpa は埋めたことにせず、60 秒後に取り直します

### `POST /jikkyo/channels/{channel}/comments`

```json
{ "author": "<利用者の ID。22 文字の base64url>", "text": "本文", "color": "red", "position": "ue", "size": "big" }
```

- `color` は `white red pink orange yellow green cyan blue`、`position` は `ue naka shita`、`size` は `big medium small` のどれか。どれも省けます。いつも 184 (匿名) を付けます
- 本文 (JSON 全体) は 4 KB までです
- 受け付けたら保存して `200 {"id":"…","at":<unix ms>}` を返し、その局の購読者全部に `src: "hub"` で配ります。NX-Jikkyo への中継は返事のあとで、結果は返しません

| 応答                               | どんなとき                                                                                                                    |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `400 {"error":"invalid_request"}`  | JSON でない・`author` の形が違う・`color` などが一覧に無い                                                                    |
| `400 {"error":"rejected"}`         | 本文が空・方針の `maxLength` (書記素で数える) を超える・改行や制御文字を含む・`/` と英小文字で始まる・方針の NG ワードを含む |
| `403 {"error":"blocked"}`          | 方針で止めた家か利用者。または、その家が直近 24 時間に書いた利用者の ID が方針の `maxAuthorsPerHome` に達していて、新しい ID で書いた |
| `429 {"error":"wait"}`             | 同じ利用者が方針の `postGapSeconds` 以内に書いた                                                                              |

**利用者の ID** は denpa が作ります (denpa のログインの subject か端末の Cookie から作ったハッシュ。中身は hub に渡りません)。
hub はそのまま持たず、`HMAC-SHA256(JIKKYO_KEY, 家の ID ‖ author)` の先頭 16 バイトの 16 進 (32 文字) にして持ちます。
`maxAuthorsPerHome` は、1 つのトークンで ID を替え続けて、間隔・止める・NX-Jikkyo のミュートを抜けられないようにするためのものです。

## 運営の方針

**運営者が決めることは `JIKKYO_POLICY` が指す JSON のファイルに置き、コードには書きません。** hub は 30 秒ごとにファイルの更新の時刻を見て、変わっていれば読み直します。
起動したときに読めなければ設定の誤りで止まります。動いている間に読めない・形が違うときは、前のものを使い続けて警告を 1 回出します。
Kubernetes では ConfigMap を `subPath` を使わずにファイルで載せます (`subPath` だと更新が届きません)。

```json
{
  "retentionDays": 30,
  "maxLength": 60,
  "postGapSeconds": 3,
  "relayToNx": true,
  "maxAuthorsPerHome": 8,
  "channels": ["jk1", "jk2", "jk4", "jk5", "jk6", "jk7", "jk8", "jk9"],
  "ngWords": [],
  "blockedHomes": [],
  "blockedAuthors": [],
  "removedComments": []
}
```

| 欄                  | 効くもの                                                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `retentionDays`     | 独自コメントを持つ日数 (1〜3650)。過ぎたものは 1 時間ごとの掃除で行ごと消します。Doa の hub は 30 日 ([rules.md](rules.md) に書いた値と同じにする)                                                            |
| `maxLength`         | 本文の長さの上限 (書記素)                                                                                                                  |
| `postGapSeconds`    | 同じ利用者が次に書けるまでの秒数。NX-Jikkyo の 0.5 秒の決まりより長くします                                                               |
| `relayToNx`         | 独自コメントを NX-Jikkyo にも書くか                                                                                                        |
| `maxAuthorsPerHome` | 家ごとに、直近 24 時間に書ける利用者の ID の数 (目安。同じ家から新しい ID で同時に書くと、少し超えることがある)                                                                                             |
| `channels`          | 購読と書き込みを受ける局                                                                                                                   |
| `ngWords`           | 含む書き込みを断り、配るもの (NX-Jikkyo のものも) からも外します。英字の大小・全角と半角の英数字と記号・ひらがなとカタカナは区別しません |
| `blockedHomes`      | 書き込みを断る家の ID                                                                                                                      |
| `blockedAuthors`    | 書き込みを断る利用者の ID (保存してある 32 文字の形)                                                                                       |
| `removedComments`   | 消す独自コメントの `id`。読み込んだときに本文を消し、控えからも外します                                                                   |

どの欄も要ります。無い・型が違うときは設定の誤りです。知らない欄は無視します。

### 削除依頼に応じるとき

**削除の依頼と問い合わせは、メール (info@doany.io) と GitHub の Issue (danything/denpa-hub) で受けます。** 書く人に示す決まりと窓口は [rules.md](rules.md) にあり、
denpa の書き込みの欄から 1 行でリンクしています。

1. `denpa-hub comments <局> <から> <まで>` をコンテナの中で動かし (`kubectl exec -n denpa-hub deploy/denpa-hub -- /app/denpa-hub comments jk1 2026-11-28T21:00+09:00 2026-11-28T22:00+09:00`)、
   その区間の独自コメントを `id・時刻・家の ID・利用者の ID・NX-Jikkyo に書けたか・消したか・本文` のタブ区切りで読みます。サーバは立てません
2. 消すものの `id` を `removedComments` に、止める人を `blockedAuthors` か `blockedHomes` に足します

- 消したものは本文を空にして行を残します (時刻と利用者の ID は、NX-Jikkyo に中継した写しを見分けるのに使います)。保存期間を過ぎれば行ごと消えます
- **NX-Jikkyo に中継した写しは、NX-Jikkyo と過去ログ API に残ります。** hub からは消せません。hub は写しを配りませんが (下の[二重にしない](#二重にしない))、
  保存期間を過ぎて行が消えると、録画の過去ログに `nx` として出ます
- 消したことを、denpa の控えや開いている画面に知らせる手段はありません (そこにはしばらく残ります)

## データの持ち方

SQLite のファイル 1 つ (`JIKKYO_DATA`)。番組ランキングと同じボリュームに別のファイルで置けます。1 台のプロセスだけが開く前提です。

| 表         | 列                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| `tokens`   | `hash` (トークンの SHA-256)・`created_at`・`used_at`                                                                       |
| `comments` | `id`・`channel`・`at`・`text`・`mail`・`home` (家の ID)・`author` (保存する利用者の ID)・`relayed` (NX-Jikkyo に書けたか)・`removed` |

- **接続元のアドレスは持ちません** (発信者情報の開示の請求に備えて残すこともしないと決めた)。購読と過去ログのリクエスト (どの家がどの局をいつ観たか) も持たず、記録にも書きません
- `JIKKYO_KEY` (32 バイト) は、保存する利用者の ID と、NX-Jikkyo に渡す Cookie を作る鍵です。替えると全員の ID が替わります

## NX-Jikkyo から受ける

局ごとに 1 つの受け手が、購読者のいる間だけ繋ぎます。最後の購読者が去って 60 秒たったら閉じます (局を行き来する人のために少し残す)。

- やり取りは、前に denpa の端末がしていたものと同じです。視聴の WS に `startWatching`、`ping` に `pong`、`seat` の間隔で `keepSeat`、
  `room` のコメントの WS (同じオリジンだけ) に `thread` を送ります。`res_from` は -1000 (繋いだときに 1 回。混む局では 15 分を埋めきれません)
- 切れたら 1 秒 → 2 秒 → … 60 秒で頭打ちで繋ぎ直します。5 回続けて失敗したら `nx: down` を配ります。毎日 4:00 のスレッドの替わり目にきれいに閉じられたら、失敗に数えず 1 秒後に繋ぎ直します
- 受けたものは控えに足し、購読者に配ります。同じ時刻・同じ本文のものは 1 つにします (繋ぎ直しで同じものが来るため。時刻は µs まであるので、別の人の同じ本文が重なることはほとんどありません)
- User-Agent は `denpa-hub/<バージョン> (+https://github.com/danything/denpa-hub)`。受けるときは Cookie を付けません

## NX-Jikkyo に書く

**NX-Jikkyo は投稿者の ID を Cookie `NX-User-ID` の SHA-1 で決めます** (確かめた。NX-Jikkyo の `server/app/utils/__init__.py` の `GenerateClientID`。Cookie が無ければ IP と User-Agent から作る)。
連投の決まり (0.5 秒以内の連投を成功に見せて捨て、それが 3 回を超えるとその接続の書き込みを全部捨てる) は視聴の WS ごとです (確かめた。`server/app/routers/websocket.py`)。
hub から全員を 1 本で書くと、全員が 1 人に見え、まとめて捨てられます。

- 利用者 (局と保存する利用者の ID の組) ごとに視聴の WS を 1 本張り、Cookie `NX-User-ID=<base64url(HMAC-SHA256(JIKKYO_KEY, "nx-user" ‖ 利用者の ID))>` を付けます。
  同じ利用者はいつも同じ NX-Jikkyo の ID になり、ほかの利用者とは分かれます。NX-Jikkyo からは家も denpa の利用者も辿れません
- `room` を受けてから `postComment` (`isAnonymous: true`、色・位置・大きさ、`vpos` は `vposBaseTime` から) を送り、`postCommentResult` を受けたら `relayed` を付けます。
  `error`・10 秒で返事が無い・繋がらないときは中継しません (送り直しません。後から古い `vpos` で書いても流れ方がずれるため)
- hub は利用者ごとに `postGapSeconds` 空けるので、NX-Jikkyo の 0.5 秒の決まりには掛かりません
- 2 分書かなければ閉じます。同時に 200 本まで (超えたら、いちばん長く書いていないものを閉じます)。`disconnect` か `NOT_ON_AIR` (4:00 の替わり目) を受けたら閉じ、次の書き込みで張り直します
- `nx: down` の間と、`relayToNx` が false のときは中継しません

## 二重にしない

中継した独自コメントは、NX-Jikkyo からも `nx` として戻ってきます。

- hub は Cookie を自分で作るので、NX-Jikkyo が付ける `user_id` (Cookie の値の SHA-1 の 16 進) も手元で計算できます
- **受けたコメントの `user_id` が hub の利用者のものなら捨てます。** 直近 1 日に書いた利用者の分をメモリに持ちます (起動したときに DB から作ります)
- 過去ログを返すときは、その区間に独自コメントを書いた利用者 (消したものを含む) の `user_id` を作り、過去ログ API のもののうち当たるものを捨てます
- 本文では見分けないので、ほかの人の同じ本文を消しません
- 過去ログ API の `user_id` が WS と同じ値かは確かめていません (推定)。違えば、録画で中継した独自コメントが 2 回出ます

## 過去ログ

- 過去ログ API を**正時からの 1 時間の塊**で取得してメモリに持ちます。リクエストの区間に掛かる塊のうち、無いものを続いた塊ごとに 6 時間までまとめて取得します
- 持つ長さ: 終わって 10 分たった塊 (過去ログに入りきったもの) は 6 時間、まだのものは 5 分、取得できなかったものは 60 秒 (止まっている相手を呼び続けない)
- 同じ塊を同時に取得しません。過去ログ API へは同時に 2 本まで・15 秒で打ち切ります。取得を待つ列は 16 回分までで、超えたら取得せずに `complete: false` を返します
- 1 リクエストが待つのは 20 秒までです (Cloudflare の 100 秒より十分短く)。始めた取得はリクエストが切れても続け、キャッシュに入れます
- 合わせて 20 万件を超えたら、30 秒より前に使われた塊のうち、いちばん長く使われていないものから捨てます
- 返事の `{"error":…}` (HTTP 200 で来る) と形の違うものは失敗です。形が一部ずれた行は飛ばし、警告を 1 回出します

## 障害のとき

| 止まったもの | 起きること                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| NX-Jikkyo    | hub は繋ぎ直し続け、`nx: down` を配ります。独自コメントは流れ、書けます (NX-Jikkyo には中継しません。戻っても後から送りません)       |
| 過去ログ API | `complete: false` で独自コメントだけを返します                                                                                        |
| denpa-hub    | denpa は繋ぎ直し続けます。端末は読めず、書けません                                                                                    |
| hub の再起動 | メモリの控えとキャッシュは消えます。独自コメントは DB に残り、局を開いたときに直近 15 分を控えに入れ直します。`epoch` が替わるので、denpa は控えの全部を受け直します |

## 公式の入口

公式のニコニコ実況のコメントを hub で受けて配るとき (ドワンゴの許諾が要ります) は、NX-Jikkyo の受け手と並ぶ局ごとの受け手を足し、同じ控えに `src: "official"` で入れます。
NX-Jikkyo が取り込んだ公式のもの (`src: "nicolive"`) と重なるので、そのときは `nicolive` を配りません。エンドポイントの形は変わりません。

連携した家の denpa が自分のトークンで公式のコメントを受けるとき (denpa の作業) は、hub は何も変えません。どの家が連携しているかを hub に教えないためです。
その家の denpa が、公式を受けている間だけ `nicolive` を捨てます。

## メモリ

| もの                   | 上限                                 | 見積もり       |
| ---------------------- | ------------------------------------ | -------------- |
| 局ごとの控え           | 3000 件 × 方針の局                   | 60 局で 27 MB ほど |
| 過去ログのキャッシュ   | 20 万件                              | 30 MB ほど     |
| 取得中の過去ログの返事 | 1 回 6 時間まで・同時に 2 本         | 20〜40 MB      |
| 中継の WS              | 200 本                               | 10 MB ほど     |
| 購読者のバッファ       | 1 本 256 件まで                      | 購読の数による |

Pod のメモリの上限は 384Mi にし、`DOTNET_GCHeapHardLimit` をその 8 割に置きます。

## レート制限

| 対象                     | 単位             | 上限                     | わけ                                         |
| ------------------------ | ---------------- | ------------------------ | -------------------------------------------- |
| 全部 (下の枠と合わせて)  | 接続元のアドレス | 120 回/分                | ランキングと同じ                             |
| `POST /jikkyo/tokens`    | 接続元のアドレス | 5 回/時・20 回/日        | 1 つの家は 1 回。CGNAT を見込む              |
| `GET …/live`             | トークン         | 30 回/分・同時に 8 本    | 局を替えるたびに 1 回。denpa は局ごとに 1 本 |
| `GET …/kakolog`          | トークン         | 30 回/分                 | 録画を開いたとき・追っかけで 5 分ごと        |
| `POST …/comments`        | トークン         | 20 回/分 (と利用者ごとの `postGapSeconds`) | 家の中で何人か書く        |

## 濫用の限界

- トークンを多く作れる人 (アドレスを多く持つ人) は、書き込みと購読の枠を増やせます。家の denpa かを確かめる方法はありません
- 止めたいときは `blockedHomes`・`blockedAuthors`・`ngWords` を足します。トークンを取り直されれば家の ID は替わります

## 記録 (ログ)

書くのは件数と、断ったわけの種類と、上流の状態 (`jikkyo nx: down` など) と、例外の型の名前だけです。
トークン・本文・利用者の ID・局・接続元のアドレスは書きません。テスト (`記録にトークンや本文や利用者を書かない`) が確かめます。

## 設定

| 環境変数        | 要るか                   | 説明                                                                                   |
| --------------- | ------------------------ | -------------------------------------------------------------------------------------- |
| `JIKKYO_DATA`   | 任意                     | SQLite のファイルの絶対パス。無ければこの機能を入れない                                |
| `JIKKYO_KEY`    | `JIKKYO_DATA` があれば要る | 32 バイトの鍵を base64 で (`openssl rand -base64 32`)                                   |
| `JIKKYO_POLICY` | `JIKKYO_DATA` があれば要る | [運営の方針](#運営の方針)の JSON のファイルの絶対パス                                   |

## プライバシー

| 相手          | 見えるもの                                                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| denpa-hub     | denpa のサーバの IP、トークン、どの局をいつ購読したか、どの区間の過去ログを取ったか、書き込み (本文・時刻・局・利用者の ID)         |
| NX-Jikkyo     | hub の IP、hub がどの局をいつ受けているか (家の区別は無い)、書き込みと利用者ごとに固定の ID                                         |
| 過去ログ API  | hub の IP と取った区間                                                                                                               |

hub に届くのは、denpa の設定で「実況」をオンにした家のものだけです (番組ランキングと同じく、オンにすることが hub に送ることへの同意。denpa の docs/architecture.md)。
hub が持つのは書き込みと家の ID・利用者の ID だけです (`retentionDays` の間)。購読と過去ログのリクエストは持たず、記録にも書きません。
NX-Jikkyo の ID は利用者ごとに固定になるので、同じ利用者の書き込みは NX-Jikkyo の側で長く結び付きます。
