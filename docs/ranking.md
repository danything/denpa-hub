# 予約数ランキング

denpa の家ごとの予約を denpa-hub で数え、よく予約されている番組の順位を、送ることに同意した denpa に返す機能の設計と実装です。
実装は denpa (家ごとの録画サーバ) と denpa-hub (このリポジトリ) の両方にまたがるので、両方の作りをここにまとめます。

**hub の 1 段階目 (トークン・票・順位) を実装しました。** コードは `src/DenpaHub/Features/Ranking/` にあります。
denpa 側 (2〜4 段階目) と、地上波の地域をまたぐまとめ (5 段階目) はまだです ([段階](#段階))。

この文書では、確かめたことには「確かめた」、推定には「推定」、まだ決めていないことには「未決」、ユーザーと決めたことには「決まった」と書きます。
数値は、とくに断りが無ければ仮の値で、理由を添えます。

## 目的

- 番組表だけでは分からない「ほかの家でよく録られている番組」を、denpa の画面で見られるようにする。見た番組はその場で予約できる
- 数えるのは denpa の利用者が自分で入れた予約だけにする。外のサービスの数字は使わない

## やらないこと

- **torne などの非公開の API は使いません。** 他社のアプリのふりをして呼ぶことになるためです。
  torne とソニーの予約ランキング (2027-02-02 に終わると告知されています) にも頼りません
- **個人の予約の履歴は持ちません。** denpa-hub が持つのは番組ごとの数だけです。二重に数えないための印は元に戻せない形で持ち、放送が終われば消します ([データ](#データの持ち方))
- 同意していない denpa からは何も送りません。ランキングを見るだけ (送らずに見る) もできません
- 番組の中身の評価 (星の数・感想) は扱いません

## 全体の流れ

```
denpa (家)                                  denpa-hub
  設定でオンにする
  ── POST /ranking/tokens ───────────────▶  トークンを作り、ハッシュだけを持つ
  ◀── 201 {token} ───────────────────────
  1 日 4 回、前に送ってからの差分をまとめて送る
  ── POST /ranking/votes (Bearer) ───────▶  1 トークン 1 番組 1 票で数える
  ── GET /ranking (Bearer) ──────────────▶  最近送ったトークンだけに返す
  ◀── 200 {entries} ─────────────────────   番組をまとめた順位と、放送の一覧
  自分が受信できる局の放送に戻して出す
  設定でオフにする
  ── POST /ranking/votes (送った分を全部取り消す)
  ── DELETE /ranking/tokens/self ────────▶  トークンを消す
```

## denpa 側

### 設定

設定の「連携」グループに、節「予約数ランキング」(`/settings/integrations#ranking`) を足します。実況 (`jikkyo`) と同じく世帯の設定で、既定はオフです。

| 置くもの     | 文言の案                                                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| スイッチ     | 「予約数ランキングに参加する」                                                                                                                 |
| 説明の 1 行目 | 「予約した番組を denpa-hub (Doa が動かすサーバ) に送り、ほかの家の予約と合わせた順位を見られるようにします。家のアドレスや名前は送りません」 |
| 詳しく       | 送るもの (下の表)、送る時刻、オフにしたときの動き、少ない人数の番組は出さないこと、この文書へのリンク                                       |
| オンのとき   | 「最後に送った時刻: 11/17(火) 18:12」。送れなかったときは「denpa-hub に届きませんでした。次の送信で再試行します」                             |

- オンにしたときは、サーバが denpa-hub からトークンを受け取り、すぐ 1 回目を送ります (オンにしてすぐランキングを見られるように)。受け取れなければスイッチをオフに戻し、「denpa-hub に届かないため、参加できませんでした」と出します
- トークンは `niconico_link` と同じく DB に 1 行で持ちます (新しい表 `ranking_link`。トークン・最後に送った時刻・次に送る時刻)。
  送った予約の控え (新しい表 `ranking_sent`。番組 ID と、ルールの予約か手の予約か) も持ち、次に送るときの差分に使います。どちらも [data.md](https://github.com/danything/denpa/blob/main/docs/data.md) の「denpa が持つもの」に足します
- denpa の画面の文言は [writing.md](https://github.com/danything/denpa/blob/main/docs/writing.md) に従います。上の案はその決まりで書いたものです

### 送る中身

**送るのは、これから放送する番組の識別と、ルールの予約か手の予約かだけです。** 家のアドレス・利用者の名前・ルールの中身 (キーワードなど)・予約した時刻は送りません。

送る予約は次のとおりです。

- 状態が「予約済み」か「競合」の予約 (`TO_RECORD_STATES`)。録らないと決めた予約 (`skipped`。コピー禁止・同じ回を録画済み) と取り消した予約は送らない
- 番組の始まりが送る時刻より後のもの。始まった番組は送らない (始まったあとの予約は順位の役に立たないため)
- 局の種別が地上波・BS・CS のもの。ケーブルの局は元の放送 (`types.origin`) が地上波・BS・CS のパススルーと再送信だけを送り、ケーブルの自主放送とスカパー！プレミアムの局は送らない (ほかの家と同じ番組だと言えないため)
- 有料放送の番組 (`programs.is_free` が 0) も送る (決まった)。CS の局はほとんどが有料放送なので、外すと CS の番組が順位にほぼ出なくなるため。
  hub は送られた中身を家と結び付けずに番組ごとに数えるだけなので ([データの持ち方](#データの持ち方))、どの有料放送を契約しているかが漏れる危険は小さいとみています

```http
POST /ranking/votes
Authorization: Bearer <トークン>
Content-Type: application/json
```

```json
{
  "v": 1,
  "add": [
    {
      "network_id": 4,
      "service_id": 211,
      "event_id": 18432,
      "start_at": "2026-11-20T21:00:00+09:00",
      "duration": 1800,
      "name": "[字]アニメ 例の番組 #7「副題」",
      "service_name": "BS11イレブン",
      "genres": [7],
      "kind": "rule"
    }
  ],
  "remove": [{ "network_id": 32736, "service_id": 1024, "event_id": 5121 }]
}
```

| フィールド              | 中身                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `network_id`            | original_network_id (`programs.network_id`)。ケーブルの再送信は元の放送の値                                         |
| `service_id`・`event_id` | `programs` の同じ名前の列                                                                                           |
| `start_at`・`duration`  | 番組の始まり (日本時間の ISO 8601) と長さ (秒)。延長などで変わったら、同じ番組を `add` にもう一度入れて書き換える    |
| `name`                  | 番組表のとおりの番組名 (`programs.name`)。整えるのは denpa-hub ([名寄せ](#名寄せ))                                  |
| `service_name`          | 局名 (`services.name`)。受信できない家の画面に、どの局の番組かを出すのに使う ([ランキングの画面](#ランキングの画面))                |
| `genres`                | ジャンルの大分類 (`programs.genres`。ARIB の lv1)                                                                    |
| `kind`                  | `manual` (手の予約。`reservations.manual` が 1) か `rule` (ルールの予約)                                             |
| `remove`                | 前に送ったが、取り消した・録らないことにした・送る条件から外れた予約。識別の 3 つだけ                               |

- 番組名を整えるのを denpa ではなく denpa-hub にするのは、denpa のバージョンが家ごとに違っても同じ決まりでまとめるためです。番組名は放送で誰にでも見えるもので、家を表しません
- 送る前に、控え (`ranking_sent`) といまの予約を比べて差分を作ります。1 回に送る `add` は 2000 件まで (仮。ふつうの家の予約は数百件なので、ルールで広く録る家でも収まる)。超えた分は次の回に回す
- denpa-hub が `401` を返したら (トークンを消された・hub のデータが消えた)、トークンを取り直し、控えを空にして、いまの予約を全部送り直します

### 送る時刻

**1 日 4 回、6 時間ごとにまとめて送ります。** 予約した瞬間が denpa-hub に分からないようにするためです。

- 送る時刻は、オンにしたときに 6 時間の中の位置を家ごとに乱数で決め、毎回そこから ±15 分を乱数でずらします。全部の家が同じ時刻に送ると hub に負荷が集まるので、ずらしておきます
- 4 回 (6 時間ごと) は仮の値です。少ないほど予約した時刻をぼかせ、多いほど順位が早く変わります。始まる 6 時間前より後に入れた予約は数えられないことがあり、それを許せる幅として 6 時間にしました
- 送れなかったときは次の回にまとめます。続けて失敗しても予約や録画には何も起きません

### オフにしたとき

1. サーバが、控えにある予約を全部 `remove` で送り、続けて `DELETE /ranking/tokens/self` を呼ぶ
2. 手元のトークンと控えを消す。ランキングの画面は出さなくなる
3. hub に届かなかったときも手元は消します。hub に残った票は、その番組の放送が終われば消えます (最長で送ってから 9 日ほど)。トークンも 30 日送らなければ消えます ([消す時期](#消す時期))

オンに戻すと、新しいトークンで始めます。前のトークンとは結び付きません。

### ランキングの画面

**画面は増やしません (決まった)。** ランキングは今ある検索の画面の中に 2 か所で出し、どちらもオンの世帯だけに出します。専用の一覧の画面 (`/ranking`) と、下のタブやヘッダーの入口は作りません。

#### 検索を言葉なしで開いたとき

最近探した言葉の下に、節「予約の多い番組」を出します。

- 行は、検索の結果の「これからの放送」と同じ行です ([screens.md](https://github.com/danything/denpa/blob/main/docs/screens.md#検索)。行から予約・取消、押すと番組の詳細)。
  [design.md](https://github.com/danything/denpa/blob/main/docs/design.md) の「何行かある一覧」に従い、件の面に 1 件ずつ乗せ、線で区切りません。1 段目の先頭に順位、2 段目に局・時刻・「予約 約 120」を出します
- 最初は 5 件で、「もっと見る」でその場に 50 件まで広げます。ほかの節の「もっと見る」と同じ押し方で、別の画面へは移りません
- 種別やジャンルの絞り込みは置きません。言葉で絞りたいときは、検索の結果の並べ替え (下) を使います
- 当てはまるものが無いときは「当てはまるものはありません」(writing.md の決まり)。hub に届かないときは「いまはランキングを読めません」と出します

#### 検索の結果を予約の多い順に並べる

結果の「これからの放送」の見出しの行に、チップ「予約の多い順」を 1 つ足します。押すと、その節の行を予約の多い順に並べ替え、もう一度押すと放送の順に戻ります。

- design.md の「選んでいるもの」に合わせ、チップは `.chip` 1 つで、入っている間は主の色の太字と下線にします。塗りません。並べ替えなので、絞り込みのように件数は付けません
- 順位の分かる番組 (hub の順位に入っている番組) を上に、その下に残りを放送の順で並べます。順位の分からない番組には「予約 約 …」を出しません
- 「録る / 録らない」の判定 (「ルールとして保存」の書く欄) と、行のボタンはそのままです
- 選んだ並べ方は覚えません (ページを離れたら放送の順に戻る)。検索の URL (`/search?q=…`) にも入れません

#### 受信できない局の番組

**受信できない局の番組も出します (決まった)。** ほかの家でよく録られている番組を知る役に立つためです。出すのは言葉なしで開いたときの節だけで、検索の結果は手元の番組表から作るので出てきません。

- hub は番組ごとに、まとめた放送の全部 (`airings`) を返します。denpa は、自分の `services` にある局の放送があればそれを選んで、ふつうの行にします
- 受信できる放送が無ければ、その番組の行は予約のボタンを出さず、押しても詳細を開きません (手元の番組表に番組が無いため)。2 段目の先頭に控えた字で「受信できない局」と出し、続けてどこで放送するかを書きます
  - 地上波で系列がある番組は、系列と地域の数を出す (「TBS 系・関東広域ほか 12 地域」)。地域の名前は hub の地域の表 (`service_id >> 10` → 地域の名前。[名寄せ](#地上波の同じ地域の中)) から引く
  - 系列が無い地上波の局 (独立局) と BS・CS は、局名と地域を出す (「TOKYO MX・東京」「BS11イレブン」)。局名は hub が票の多いもの (`service_name`) を返す
- 順位は hub の順位のまま出し、受信できない番組を飛ばして振り直しません

#### 番組表と番組の詳細

- 番組表のマスには印を付けません。design.md の「番組表のマス」では、時刻の後ろの印は予約の状態 (予約済み・録画中・競合) を示すもので、そこに順位の印を足すと、印の意味が予約の状態だけでなくなるためです
- 番組の詳細は、順位に入っている番組だけ、ジャンルの行に「予約の多い番組の 12 位」を足します。新しい画面にはならず、番組表から開いたときにも順位が分かります

## denpa-hub 側

### エンドポイント

どの応答にも、ニコニコの中継と同じヘッダ (`Cache-Control: no-store` など。`Hub.cs`) を付けます。本文は JSON で、エラーは `{"error":"<名前>"}` です。

| メソッドとパス                  | 認証   | 中身                                                                                                                       |
| ------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------- |
| `POST /ranking/tokens`          | 無し   | トークンを作って `201 {"token":"<43 文字>"}` を返す                                                                        |
| `DELETE /ranking/tokens/self`   | Bearer | そのトークンを消す。`204`                                                                                                  |
| `POST /ranking/votes`           | Bearer | `add` と `remove` を数えに入れ、最後に送った時刻を書き換える。`200 {"accepted":<件数>,"rejected":<件数>}`                  |
| `GET /ranking`                  | Bearer | 順位を返す。クエリは `limit` (既定 50、最大 300)。denpa の画面は種別とジャンルで絞らないので、絞るクエリは持たない       |

- トークンは 32 バイトの乱数を base64url (パディングなし) にしたものです。hub はトークンそのものを持たず、SHA-256 だけを持ちます
- `POST /ranking/votes` は、中身を 1 件ずつ確かめ、通らないものは数えずに `rejected` に数えます (全体は断らない)。
  確かめるのは、`network_id` が地上波・BS・CS の範囲か、始まりが今より後で 9 日先までか、長さが 24 時間以下か、番組名が 1〜120 文字か、局名が 1〜40 文字か、`genres` が 0〜15 か、です
  - `network_id` は BS の 4、CS の 6・7、地上波の 0x7880〜0x7FE8 だけを受けます (ARIB TR-B14・TR-B15。denpa の `types.ts` の `origin` と同じ範囲)。4K の BS (0x000B) は受けません
  - `start_at` は時差の付いた ISO 8601 (`2026-11-20T21:00:00+09:00` か `…Z`) だけを受けます。番組名と局名は前後の空白を除いて数え、改行などの制御文字を含むものは受けません
  - `remove` は、そのトークンが票を入れていない放送なら何もせず、`accepted` に数えます (同じ取り消しを送り直してもよいように)
- 本文の全体が読めないときは断り、最後に送った時刻も書き換えません。JSON でない・`add` や `remove` が配列でないときは `400 {"error":"invalid_request"}`、
  `v` が 1 でないときは `400 {"error":"unsupported_version"}`、`add` が 2000 件か `remove` が 5000 件を超えるときは `400 {"error":"too_many_items"}` です。本文は 1 MiB まで
- 空の `add` と `remove` でも、最後に送った時刻は書き換えます (予約が 0 件の家もあるため)。`add` と `remove` は省いてもかまいません。
  そのため、見る権利を得るのに予約は要りません。この絞りは「参加していない denpa には見せない」ためのもので、順位を秘密にするものではありません
- `GET /ranking` の `limit` が 1〜300 の整数でなければ `400 {"error":"invalid_request"}` です

`GET /ranking` は次の形で返します。

```json
{
  "v": 1,
  "generated_at": "2026-11-17T18:00:00+09:00",
  "entries": [
    {
      "rank": 1,
      "votes": 120,
      "name": "アニメ 例の番組 #7「副題」",
      "genres": [7],
      "affiliation": null,
      "airings": [
        {
          "network_id": 4,
          "service_id": 211,
          "event_id": 18432,
          "start_at": "2026-11-20T21:00:00+09:00",
          "service_name": "BS11イレブン",
          "region": null
        }
      ]
    }
  ]
}
```

- `votes` は重みを掛けた数 ([ルールの予約の重み](#ルールの予約の重み)) を 5 の倍数に切り下げたものです。1 票ずつの増減が見えると、自分の票を足し引きしてほかの家の票を推し量れるためです
- `airings` は、その番組としてまとめた放送の全部です (地上波の同時ネットなら地域の数だけ)。どれを出すかは denpa が決めます。
  hub に家の地域を伝えないためで、見るときに hub が知るのはトークンだけです
- `affiliation` は地上波の系列 (「TBS 系」など。無ければ null)、`region` は地上波の放送の地域の名前 (「関東広域」など。BS・CS は null) です。受信できない番組の行に使います。
  系列と地域の表は 5 段階目で足すので、1 段階目の hub はどちらも null を返し、`airings` も 1 つだけです
- 並びは、切り下げた `votes` の多い順で、同じ数の中は始まりの早い順です。切り下げる前の数で並べると、並びから 1 票ずつの差が見えるためです。`rank` は 1 から振った並びの順です
- 切り下げて 0 になる番組 (ルールの予約だけで 5〜9 トークン) は出しません
- 検索の結果を並べ替えるときは、denpa が手元の番組と `airings` を突き合わせます。言葉は hub へ送りません
- 順位は 10 分ごとに作り直してメモリに置き、全部のトークンに同じものを返します。上の 300 件だけを持ちます

### 認証

- `Authorization: Bearer <トークン>` の SHA-256 を `tokens` の表で引きます。無ければ `401 {"error":"invalid_token"}`
- `GET /ranking` は、最後に送った時刻が 7 日以内のトークンだけに返します。古ければ `403 {"error":"inactive"}`。denpa は送ってから見直します
- 7 日は仮の値です。denpa は 6 時間ごとに送るので、ふつうは数時間以内です。サーバを止めた家・hub に数日届かなかった家が、戻ってすぐ見られなくなるのを避けるため、長めにしました

### レート制限

ニコニコの中継と同じく、1 分の固定の枠で数えます (超えたら 429)。発行だけは 1 時間と 1 日の枠も足します。
接続元ごとの合計の枠と、エンドポイントごとの枠の両方を通ったものだけを通します。断るときの返事はニコニコの中継と同じ短い文 (`Hub.cs`) です。

| エンドポイント                          | 単位                   | 上限                     | わけ                                                                                      |
| --------------------------------------- | ---------------------- | ------------------------ | ----------------------------------------------------------------------------------------- |
| `POST /ranking/tokens`                  | 接続元のアドレス       | 5 回/時・20 回/日        | 1 つの家は一度だけ。CGNAT で多くの家が 1 つのアドレスを共有しうるので、1 回にはしない     |
| `POST /ranking/votes`・`DELETE …/self`  | トークン               | 4 回/分                  | 1 つの家は 6 時間に 1 回。失敗したときの再試行の分を見込む                               |
| `GET /ranking`                          | トークン               | 30 回/分                 | 人が検索の画面を開いたときと並べ替えたとき (denpa のサーバは 10 分ためておく)           |
| 上の 3 つの合計                         | 接続元のアドレス       | 120 回/分                | ニコニコの中継の `/niconico/token` と同じ考え                                             |

### データの持ち方

**SQLite のファイル 1 つを、ボリュームに置きます。** ニコニコの中継は状態を持ちませんが、この機能は状態を持ちます。

- Deployment は 1 台のまま (`replicas: 1`)、入れ替えは `strategy: Recreate` にします (SQLite のファイルを 2 つのプロセスで開かないように)。
  ボリュームは Doa のクラスタのほかのアプリと同じく、ノードのローカルの PVC (`local-path`) にします。`readOnlyRootFilesystem` はそのままで、`/data` だけ書けるようにします (`deploy/deployment.yaml`)
- バックアップは取りません。中身はどれも放送が終われば消すもので、失えば順位が空になり、denpa がトークンを取り直して送り直せば戻るためです (`401` のときの動き)
- 確かめた: `Microsoft.Data.Sqlite` 11.0.0 (SQLitePCLRaw 3.0.5、SQLite 3.53.4) は、Native AOT で警告なしに組め、distroless の `cc` のイメージの上で読み書きできる。
  組み込みの `libe_sqlite3.so` を実行ファイルの隣に置けば足りる (`Dockerfile`)。CI の「Smoke (ranking)」が、組んだイメージをルートを読み取り専用にして動かし、毎回確かめる
- SQLite の一時ファイルはメモリに置きます (`temp_store = MEMORY`)。書けるのが `/data` だけのためです。書き込みは WAL です
- 1 つの接続をロックで順に使います。書き込みは 1 回の送信で数千行なので、待ちは短いとみています (推定)
- PostgreSQL や Redis は選びません。1 台で済む量 (下の見積もり) で、別のサーバを立てて持つ手間に見合わないためです
- 表の形を変えたときは、起動したときに中身を捨てて作り直します (`PRAGMA user_version`)。中身は消えてよいもので、denpa が送り直せば戻るためです

表は 4 つです。

| 表        | 列                                                                                                     | 中身                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| `tokens`  | `hash` (トークンの SHA-256)・`created_on` (日付)・`sent_at` (最後に送った時刻)                        | 発行したトークン                                                         |
| `airings` | `network_id`・`service_id`・`event_id`・`end_at`・`manual`・`rule`                                     | 票の入った放送と、手の予約とルールの予約の数                             |
| `labels`  | `network_id`・`service_id`・`event_id`・`field`・`value`・`votes`                                      | 放送ごとの番組名・局名・ジャンル・時刻と、その値を送ったトークンの数     |
| `marks`   | `mark` (下の鍵付きのハッシュ)・`kind`・`expires_on` (日付)・`labels` (送った値の鍵付きのハッシュ)      | 二重に数えないための印。どのトークンか、どの番組かは書かない             |

- **印は `HMAC-SHA256(RANKING_MARK_KEY, トークンそのもの ‖ network_id ‖ service_id ‖ event_id)` の先頭 16 バイトです。** hub が持つのはトークンの SHA-256 だけなので、DB と鍵が両方漏れても、
  印からどの家がどの番組を予約したかは辿れません (トークンそのものが無いと、印を作り直して突き合わせられないため)。300 万行でも 16 バイトで重なる見込みは無視できます
- `marks` は `WITHOUT ROWID` の表にし、印の値の順に並べます。入れた順番が残ると、同じ回に送った印を束ねて 1 つの家の予約に戻せてしまうためです。入れた時刻の列も持ちません
- `expires_on` は、その放送の終わり (送られた中でいちばん遅いもの) の翌日の日付 (UTC) です。日付にするのは、番組の終わりの時刻から番組を絞り込めないようにするためです。
  印を放送より先に消すと、同じトークンの票を二重に数えうるので、放送の終わりが延びたら `expires_on` も延ばします
- 番組名・局名・ジャンル・時刻 (始まりと長さ) は、どれも送ったトークンの多い値を出します (`labels`。同じ数なら文字の順で先の値)。1 つのトークンで有名な番組の名前や時刻を書き換えられないようにするためです
- 同じトークンが値を変えて送り直したとき (延長で時刻が変わったなど) と `remove` のときは、前に送った値から 1 つ減らします。
  どの値を送ったかは、印の `labels` に `HMAC-SHA256(RANKING_MARK_KEY, トークンそのもの ‖ 放送の識別 ‖ 欄 ‖ 値)` の先頭 8 バイトを欄ごとに持ち、その放送の値の候補と突き合わせて見つけます。印と同じく、トークンそのものが無いと突き合わせられません
- 設計では放送の数を `counts`、名前の数を `names` に分けていましたが、実装では数を `airings` に入れ、名前の表をジャンルと時刻にも広げて `labels` にしました。
  `airings` の `group_id` (地域をまたいでまとめた番組) は 5 段階目で足します
- 見積もり (推定): 参加する家が 1 万、1 家 300 件の予約で、`marks` が 300 万行・1 行 60 バイトほどで 200 MB 前後。`airings` は 9 日分の放送 (全国の地上波と BS・CS で数万) です

設定には次の 2 つを足します。どれも `<名前>_FILE` でファイルから読めます。

| 環境変数           | 要るか | 説明                                                                                              |
| ------------------ | ------ | ------------------------------------------------------------------------------------------------- |
| `RANKING_DATA`     | 任意   | SQLite のファイルの場所。`/data/ranking.db` のような絶対パス。無ければ `/ranking/*` は 404 (ほかの人が hub を立てるときに外せるように)。開けなければ起動のときに止まる |
| `RANKING_MARK_KEY` | `RANKING_DATA` があれば要る | 印の鍵。32 バイトを base64 で (`openssl rand -base64 32`)。替えると、それまでの印と突き合わせられなくなるので、替えるときは `marks`・`labels`・`airings` を空にする |

### 消す時期

| もの                   | 消す時期                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------- |
| `marks`                | `expires_on` を過ぎたら (1 時間ごとに消す)                                            |
| `airings`・`labels`    | 放送が終わってから 1 日たったら。`remove` で票が 0 になったら、そのとき             |
| `tokens`               | `DELETE /ranking/tokens/self` を受けたとき。30 日送らなかったとき (一度も送っていなければ、発行してから 30 日) |
| 順位 (メモリ)          | 10 分ごとに作り直す。始まった番組は入れない                                           |

- 30 日は仮の値です。見る権利の 7 日より長くし、しばらく止めていた家がトークンを取り直さずに戻れるようにしました
- 消すのは、順位を作り直す 10 分ごとの処理のうち、前に消してから 1 時間たった回です。起動したときにも 1 回消します
- ログには、ニコニコの中継と同じく、トークン・送られた番組の一覧・接続元のアドレスを書きません。書くのは件数と、断ったわけの種類だけです

## 名寄せ

**同じ番組への予約を 1 つにまとめます。まとめきれないものは別の番組として数えます。** 違う番組を 1 つにまとめるより、同じ番組が 2 行に分かれるほうが害が小さいためです。

### BS・CS

`network_id`・`service_id`・`event_id` が同じなら同じ放送です。BS・CS の局は全国で同じなので、これで足ります。
event_id は 16 ビットで使い回されますが、hub は放送が終わってから 1 日で消すので、9 日の間に同じ局で重なることは無いとみています (推定)。

同じ番組を BS と地上波で別の時刻に流すもの、BS で再放送するものはまとめません。どちらも別の放送で、予約も別に入るためです。

### 地上波の同じ地域の中

同じく `network_id`・`service_id`・`event_id` でまとめます。地上波の service_id は全国で重ならないので (ARIB TR-B14。denpa の `src/lib/jikkyo/terrestrial.ts` の前提)、同じ放送は同じ地域の家からしか来ません。

地域は service_id の上位 6 ビット (`service_id >> 10`) で分かります。denpa の `terrestrial.ts` の全 247 局で、この値と表の注記の地域 (1 が関東広域、2 が近畿広域、23 が東京、62 が沖縄など) が 1 対 1 に揃うことを確かめました。
規格 (TR-B14) の地域の割り当てがこの形だというのは推定で、表に無い局 (独立局など) では確かめていません。
hub はこの値から地域の名前を引く表 (59 行。上で確かめた対応) を持ち、受信できない家の画面に出す地域の名前 (`region`) に使います。

### 地上波の地域をまたぐもの

**同じ系列で、始まりが 10 分以内で、整えた番組名が同じか片方がもう片方を含む放送を、1 つにまとめます。** 同時ネットの番組 (キー局の番組を系列の地方局が同じ時刻に流すもの) が地域の数だけ分かれないようにするためです。

#### 系列をどこから取るか

次のことを確かめました。

- denpa は BIT を読みません。`packages/arib` に BIT と拡張ブロードキャスタ記述子 (0xCE) の読み取りは無く、データ放送の NVRAM の系列の領域 (`nvram://NN;group/`) も、系列が分からないので局ごとに分けています (`src/lib/bml/nvram.ts` の注記)
- SDT と NIT から denpa が読むのは局名・サービス種別・部分受信・リモコンキー ID などで、系列は入っていません
- denpa には局から系列を引ける表がすでにあります。`src/lib/jikkyo/terrestrial.ts` は公開されている対応表 (MIT。出どころは denpa の docs/licenses.md) を写したもので、地上波の service_id を実況のチャンネル (jk1 = NHK総合、jk2 = NHK Eテレ、jk4 = 日本テレビ系、jk5 = テレビ朝日系、jk6 = TBS 系、jk7 = テレビ東京系、jk8 = フジテレビ系) に当てています。
  系列の地方局はキー局のチャンネルに当たっているので、この番号がそのまま系列になります

推定: BIT の拡張ブロードキャスタ記述子の affiliation_id は系列を表す (データ放送の系列の NVRAM はこの値で分ける)。ただし実際の放送で値を読んで確かめてはいません。

**案: hub が service_id → 系列の表を持ちます。** 中身は denpa の `terrestrial.ts` と同じ表を C# に写したもので、MIT の表示を添えます。

- まとめるのは hub なので、表も hub に置けば、表を直したときに全部の家の票へ一度に効きます。denpa は service_id を送るだけで足ります
- 表に無い局 (独立局・表に載っていない局) は系列なしとし、地域をまたいではまとめません
- NHK 総合と Eテレも系列 (jk1・jk2) として扱います。全国放送の番組は地域の局を 1 つにまとめ、地域の番組は番組名が違うのでまとまりません
- BIT を読む案は選びません。denpa のスキャンとエージェントに読み取りを足し、全部の家がスキャンし直すまで揃わないためです。表で困る局が出てきたら考え直します

#### 整えた番組名

hub が `name` から作ります。denpa の `src/lib/server/title.ts` の `displayTitle` と `searchable` と同じ考えで、次の順に当てます。

1. NFKC で全角の英数と記号を半角に寄せ、小文字にする (`Ｖｅｎｕｅ１０１` → `venue101`)
2. 番組表の飾りを落とす。`[字]` `[デ]` `[再]` `[新]` `[終]` `[解]` `[二]` `[多]` `[SS]` `[無料]` `[生]` と、同じ意味の外字 (🈟 🈡 🈑 など)、`【】` で囲んだ飾り (`【新】` `【字】`)
3. 先頭の枠の名前を落とす (`<アニメギルド>`)
4. 局が付ける前置きを落とす (下の「前置きを落とす」)
5. 空白と、次の記号を落とす。`・` `･` `!` `?` `~` `〜` `:` `|` `-` `「」` `『』` `()` `[]` `【】` `♪` `★` `☆` `◆` `◇` `▼` `▽`。長音 (`ー`) と数字は落とさない
6. 残りが 4 文字に満たなければ、地域をまたいではまとめない (その放送だけで数える)。短い名前 (「ニュース」) はどの局にもあり、取り違えやすいため

#### 前置きを落とす

**地方局は、キー局と同じ番組の名前の前に、局名や枠の名前を足すことがあります。これも落としてからまとめます (決まった)。** 落とすのは名前の先頭にあるものだけで、名前の途中と後ろは触りません。

- 先頭の局名。hub の系列の表にある局名と、その略称 (`ＴＢＳ`・`ＭＢＳ`・`ＣＢＣ`・`日テレ`・`ＫＴＶ` など) を表で持ち、名前の先頭がそれで始まれば落とす。局名は系列の表と一緒に持つ
- 先頭の枠の名前。同じ枠を局ごとに違う名前で流すもの (`日曜劇場` の前の `ＴＢＳ`、`アニメイズム` の前の `ＭＢＳ`) は、局名を落とせば揃う。枠の名前そのもの (`日曜劇場`) は、局が揃って付けるので残す
- 先頭の `【】` で囲んだ前置き (`【ドラマ】` `【特番】` `【アニメ】`)。中身によらず落とす
- 先頭の `「」` `『』` で囲んだもので、後ろに続きがあるもの (`「大阪」ローカルの…` のような地域の前置き)。続きが無い (名前の全部が括弧の中) ときは、括弧を外すだけで中身は残す

例: `[字]ＴＢＳ日曜劇場「例のドラマ」　第３話` と `日曜劇場 例のドラマ 第3話[字][デ]` は、先頭の `ＴＢＳ` を落とすと、どちらも `日曜劇場例のドラマ第3話` になってまとまります。

前置きを落としても揃わないときは、**片方の整えた名前がもう片方に含まれていれば、まとめます。** ただし次のすべてに当てはまるときだけです。

- 系列が同じで、始まりが 10 分以内
- 短いほうの名前が 8 文字以上で、長いほうの名前の 6 割以上の長さがある
- 話数が読めるなら、話数が同じ (denpa の `title.ts` の `parseTitle` と同じ読み方を hub に写す)

例: `例のドラマ第3話` と `日曜劇場例のドラマ第3話` は、系列と時刻が合い、短いほうが 8 文字以上で 6 割を超えるのでまとまります。`ニュース` と `ニュース7` は短いほうが 8 文字に満たないので、まとめません。

**取り違えの危険があります。** 含まれるかで見る決まりは、同じ系列の同じ時刻に、名前の似た別の番組 (同じ枠のミニ番組と本編、地方局が差し替えた別の番組) があると、2 つを 1 つにまとめてしまいます。
取り違えると、別の番組の票が混ざり、その番組が実際より上に出ます。片方の地域の家には、自分の地域では流れない番組の名前と数が見えます (行の局は自分の局の放送になるので、予約は自分の局の番組に入ります)。

- まとめるのは順位を作るときだけで、票は放送ごとに持つので、決まりを直せば次に順位を作るときから元に戻ります
- 文字数の下限 (8 文字・6 割) は仮の値です。順位に出た番組を Doa がときどき確かめ、取り違えが見つかれば下限を上げます
- 前置きの表 (局名と略称) は、まとまらなかった名前を見て足していきます

#### 始まりの時刻の幅

10 分 (仮) です。同時ネットは同じ時刻に始まりますが、局ごとの番組表の区切り (前の番組の延長・地方局の短い番組) で数分ずれる例を許します。
同じ名前の毎日の番組 (ニュースなど) は 24 時間離れているので、10 分なら隣の日の回とまとまりません。

#### まとめきれないとき

- 番組名が違う・系列が無い・時刻が離れているものは、別の番組として数えます。順位にも別の行で出ます
- まとめた中で始まりの時刻が違うものは、`airings` に放送ごとの時刻を入れます。denpa は自分の局の時刻で出します
- 1 つの地域から同じ系列の放送が 2 つ以上まとまろうとしたとき (同じ名前の番組を同じ地域で続けて流すなど) は、まとめません。同じ地域の家が違う放送を予約しているので、別の番組とみます
- まとめるのは順位を作るときだけで、票 (`counts`) は放送ごとに持ちます。決まりを直したら、次に順位を作るときから効きます

## プライバシーと悪用

### 同意

- 既定はオフです。設定のスイッチをオンにしたときだけトークンを取り、送り始めます。説明の 1 行目に、何を送り、何を送らないかを書きます
- 送るのも見るのも同じスイッチです。見るだけはできません (見るなら送る)
- オフにすると、送った票を取り消してからトークンを消します ([オフにしたとき](#オフにしたとき))
- 世帯の設定なので、オンにするのは設定を変えられる人 (ログインのある家では、ログインした人) です

### 送る中身から家が分かる危険

- **予約の組み合わせは家ごとに違うので、1 回分の送信は家の目印になりえます。** hub はトークンごとの組み合わせを残さず (`marks` からは戻せない)、送られた中身もログに書きません。
  ただし、動いている hub の中では、1 回分の送信が届いた間だけ、トークンとその中身と接続元のアドレスが並んでいます。hub を動かす Doa を信用することが前提で、Doa からも隠す作りではありません
- 地上波の service_id から、家のおおよその地域 (都道府県か広域) が分かります。地域ごとにまとめるのに要るので送ります。見るとき (`GET /ranking`) は地域を送りません
- 予約した時刻は送りません。送る時刻を 6 時間ごとにまとめ、家ごとにずらすので、予約を入れた時刻は 6 時間の幅でしか分かりません
- ルールのキーワードは送りません。ルールの予約か手の予約かの 1 ビットだけです
- 有料放送の予約も送ります。どの局を契約しているかは予約の組み合わせから推し量れますが、hub は組み合わせを残さず番組ごとに数えるだけで、5 未満のトークンの番組は出しません。漏れる危険は小さいとみて、CS の番組を順位に出すほうを取りました ([送る中身](#送る中身))

### 少ない人数の番組は出さない

**票を入れたトークンが 5 未満の番組は、順位に出しません。** 1 つや 2 つの家しか予約していない番組を出すと、その家が何を録っているかを人が推し量れるためです。

- 数えるのはトークンの数 (手の予約とルールの予約の合計) で、重みを掛ける前の数です
- 5 は仮の値です。参加する家が少ないうちは、これで多くの番組が出なくなります。参加が増えたら上げることを考えます
- `votes` を 5 の倍数に切り下げて返すのも、1 票ずつの増減を見せないためです

### 偽の票

**偽の票には、レート制限と中身の確認のほかに、今は対策を入れません (決まった)。** 限界は下に書いたままにし、困ったことが起きてから考え直します。

1 トークン 1 番組 1 票です。同じトークンから同じ番組を何度送っても 1 票で、`kind` が変わったら数え直します。

入れるのは次のものです。

- トークンの発行に、接続元のアドレスごとのレート制限 (5 回/時・20 回/日) を掛けます
- 1 回の送信の `add` は 2000 件まで、番組は 9 日先まで、と中身を確かめます
- 番組名は票の多いものを出すので、少ないトークンで有名な番組の名前を書き換えられません

限界もあります。

- アドレスを多く持つ人 (クラウドの IP を借りる人) は、トークンを多く作って順位を動かせます。トークンを作るのに家の denpa であることを確かめる方法が無いためです
- hub は番組表を持たないので、送られた番組が本当にあるかを確かめられません。5 つのトークンを作れば、無い番組を順位に出せます
- 困ったときに足せる対策には、発行したばかりのトークンの票を 1 日数えない、発行に計算の手間 (proof of work) を求める、順位に出た番組名を Doa が確かめて手で消す、があります。どれも今は入れません
- 順位は「denpa の利用者の予約の目安」として出し、正確な数字としては出しません

## 限界と未決のこと

### 利用者が少ないうちは順位が安定しない

参加する家が少ないうちは、5 つのトークンの決まりで多くの番組が出ず、出た番組も 1 つの家の予約で順位が大きく動きます。
最初は順位の上のほうだけ (50 件まで。仮) を出し、参加が増えてから広げます。どのくらいの家が参加すれば順位が意味を持つかは、まだ分かりません。

### 遅れて放送する番組

地方局が数日あとに流す番組 (遅れネット) は、始まりの時刻が離れているのでまとめません。その地域の家の票だけで数えるので、5 つのトークンに届かず出ないことが多いはずです。
同じ回として数えるには「同じ回」を見分ける決まりが要ります (denpa の `episode.ts` の `sameEpisode` のようなもの)。これは段階の最後に考えます。

### ルールの予約の重み

**ルールの予約は 0.5 票、手の予約は 1 票として順位を付けます (仮)。** ルールは広い条件で多くの番組に当たるので、手で選んだ予約より「観たい」の強さが弱いとみるためです。
hub は手の予約とルールの予約を別に数えて持つので (`counts` の `manual`・`rule`)、重みは順位を作るときに掛け、データを作り直さずに変えられます。

### 数値の仮の値

| 値                         | 仮の値          | 理由                                                                 |
| -------------------------- | --------------- | -------------------------------------------------------------------- |
| 送る回数                   | 1 日 4 回       | 予約した時刻を 6 時間の幅にぼかし、順位も 1 日のうちに変わる         |
| 見る権利                   | 送ってから 7 日 | 止めていた家が戻ってすぐ見られなくならない                           |
| トークンを消す             | 30 日送らない   | 見る権利より長く、取り直しを減らす                                   |
| 出す番組のトークンの数     | 5 以上          | 1・2 の家の予約を推し量れないようにする                              |
| ルールの予約の重み         | 0.5             | 広い条件で当たる分を軽くする                                         |
| 返す `votes` の刻み        | 5               | 1 票ずつの増減を見せない                                             |
| 地域をまたぐ時刻の幅       | 10 分           | 番組表の区切りのずれを許し、隣の日の回とまとめない                   |
| 地域をまたいでまとめる名前 | 4 文字以上      | 短い名前はどの局にもあり、取り違えやすい                             |
| 含まれるかで見る名前       | 8 文字以上・6 割以上 | 名前の似た別の番組を、1 つにまとめないようにする                 |
| 出す件数                   | 50 件まで       | 参加が少ないうちは下の方の順位が安定しない                           |
| 1 回の `add`               | 2000 件まで     | ふつうの家の予約は数百件                                             |
| 発行のレート制限           | 5 回/時・20 回/日 | 1 つの家は 1 回。CGNAT を見込む                                    |

### 決まったこと

| こと                       | 決まったこと                                                                                     | 書いた所                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| 有料放送の番組             | 送る。外すと CS の番組がほぼ出ない。家と結び付けずに数えるので、契約が漏れる危険は小さい         | [送る中身](#送る中身)                       |
| 地方局が付ける前置き       | 落としてからまとめる。片方がもう片方を含むときも、条件を満たせばまとめる                         | [前置きを落とす](#前置きを落とす)           |
| 画面                       | 増やさない。検索を言葉なしで開いたときの節と、検索の結果の並べ替えだけ。番組表のマスに印は付けない | [ランキングの画面](#ランキングの画面)       |
| 受信できない局の番組       | 出す。予約のボタンは出さず、「受信できない局」と系列や局名を出す                                 | [受信できない局の番組](#受信できない局の番組) |
| 偽の票                     | レート制限と中身の確認だけ。限界は文書に残す                                                     | [偽の票](#偽の票)                           |

ほかに未決のことは、上の表の仮の値です。参加の数を見てから決めます。

## 段階

小さく出せる順です。各段階は、前の段階が動いてから始めます。

| 段階 | どこ  | 中身                                                                                                                                                             |
| ---- | ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | hub   | トークンと票と順位。4 つのエンドポイント、SQLite とボリューム、消す処理、5 つのトークンの決まり。地上波も数えるが、順位は放送ごとのまま (地域をまたいでまとめない)。実装済み |
| 2    | denpa | 設定と送信。設定の節、トークンの取得、6 時間ごとの差分の送信、オフにしたときの取り消し。画面にはまだ順位を出さず、「最後に送った時刻」だけを出す                  |
| 3    | denpa | 検索を言葉なしで開いたときの節「予約の多い番組」。受信できる局の番組は行から予約でき、受信できない局の番組は局名と地域を添えて出す                               |
| 4    | denpa | 検索の結果の「予約の多い順」のチップと、番組の詳細の順位の 1 行                                                                                                  |
| 5    | hub   | 地上波の地域をまたぐまとめ。系列と地域の表、整えた番組名、前置きを落とす決まり、含まれるかで見る決まり、10 分の幅                                                 |
| 6    | 両方  | 参加の数を見て、仮の値 (5 つのトークン・重み・送る回数・名前の文字数) を見直す。遅れネットの扱いもここで考える                                                    |
